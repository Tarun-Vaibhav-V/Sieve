Latency

Cold questions and warm questions

A cold question is the first one in a conversation: the model has never seen this prompt, so every token is prefilled. Warm questions come later, and most of their prompt is a prefix the server already holds in its KV cache. The raw prompt is strongest in the warm case. Sieve's main case is cold prefill and headroom.

The cache-vs-compress conflict

Compression breaks the KV cache unless the bytes stay put

The ledger stores the exact string emitted for each segment and replays it on later turns. In the benchmark, C4 averaged 45% prefix reuse with 84 ms of Sieve CPU time per call. C5, which re-routes and re-compresses every turn, averaged 13% reuse and 2022 ms of CPU per call.

Cold prefill fit used for the timing estimate: t(n) = 1.699 ms·n + 0.0419 µs·n².

Externalize break-even

When does hiding a document stop paying?

Each conversation holds a large archived document that Sieve externalizes. As the share of questions that actually need it grows, Sieve pays for more expansion round-trips. The curves do not cross in the swept range.
